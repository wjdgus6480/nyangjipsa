# 04. 냥집사 챗봇 UI 구현 기록

지도 PoC(`02_frontend/map-poc`)에 브랜드 로고 기반 AI 챗봇 화면을 붙였다. 백엔드·DB는 수정하지 않았다.

## 1. 조사 결과 (작업 전 상태)

| 항목 | 실제 구성 |
|---|---|
| 프론트엔드 | React 아님. `map-poc/index.html` 한 장 + 순수 JS, 빌드 도구 없음 (`serve.sh` → python http.server :5520) |
| 지도 | 네이버 지도 JS v3, 데이터는 `GET /api/places/nearby` |
| 챗봇 백엔드 | PR #4 로 이미 있음: `POST /api/chat` (Gemini, 키는 서버 `.env`), 병원·장소는 서버가 DB 에서 붙임 |
| 챗봇 화면 | 없음 |

React 프로젝트가 아직 없으므로 **기존 PoC 방식(의존성 없는 순수 JS)** 을 유지하고, 챗봇을 독립 모듈로 분리했다. 나중에 React 로 옮길 때는 `chat-core.js` 를 그대로 쓰고 화면만 컴포넌트로 바꾸면 된다.

## 3. 브랜드 디자인 시스템 (`chatbot.css` 의 `.nj-root`)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--nj-primary` | `#8BE4FF` | 공식 Primary: 헤더, 사용자 말풍선, 주요 버튼 |
| `--nj-primary-strong` | `#4CC9EF` | 테두리·포커스·hover |
| `--nj-secondary` | `#E8F9FF` | Primary 연한 톤: 칩, hover 배경 |
| `--nj-bg` | `#FFFFFF` | 배경 |
| `--nj-text` | `#1B2A41` | 짙은 네이비 본문 |
| `--nj-border` | `#D6E3EA` | 연한 블루그레이 |

- Primary 가 밝은 색이라 그 위 글자는 흰색이 아니라 네이비(`--nj-text`)를 써서 대비를 확보했다.
- 로고는 `object-fit: contain` + 정사각 비율 고정. 둥근 사각형 틀에 넣어 찌그러지거나 캐릭터가 잘리지 않는다.
- 로고 사용 위치: 플로팅 버튼, 채팅창 헤더, 환영 화면, AI 메시지 프로필, 로딩 표시.

## 4. 동작

- **플로팅 버튼**: 우측 하단 고정, hover 시 안내 말풍선. 클릭 → 채팅창.
- **채팅창 헤더**: 로고·서비스명·상태(대화 가능 / 답변 작성 중 / 연결 확인 필요), 대화 초기화, 닫기(Esc 도 가능).
- **입력**: Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 Enter 무시, 500자 제한(서버와 동일).
- **환영 화면**: 로고, 인사, 역할 안내, 추천 질문 5개(누르면 바로 전송. "내 주변…"은 위치 권한을 먼저 요청).
- **AI 응답**: 답변 + 되묻는 질문, 중요 키워드(중요도 색 구분, 마우스를 올리면 이유), 선택지 버튼(누르면 그 문장으로 이어서 질문), 면책 문구.
- **오류**: 429/503/네트워크별 안내 + "다시 시도"(같은 질문을 중복으로 쌓지 않음).
- **검색 위치**: 기본은 지도 중심. "내 위치"를 허용하면 그 위치. 서버가 위치를 요구하면 선택 버튼 표시.

### 병원 카드와 지도 연결

- 카드 정보는 **서버 응답(DB)만** 사용한다. 프론트에서 병원 정보를 만들지 않는다.
- 카드: 이름, 거리, 주소, 전화, (있으면) 진료비 참고 4개 — 버튼 "지도에서 보기", "전화".
- 주소가 일부 비공개인 업소(자택 영업 가능성)는 서버가 좌표·전화를 주지 않으므로 지도 버튼이 꺼진다.
- "지도에서 보기" → `chatMapBridge.focus()` 가 해당 위치로 이동, 마커와 정보창 표시. PC 에서는 채팅창에 가리지 않게 왼쪽으로 비켜서 보여 주고, 모바일에서는 채팅을 닫고 지도를 보여 준다.
- 챗봇은 지도 내부를 모르고 `getCenter()`, `focus(card)` 두 함수만 쓴다.

### 병원 테이블이 비어 있을 때 (현재 개발 DB)

0004 로 생긴 `hospitals` 테이블이 아직 비어 있어 `/api/chat` 의 `hospitals` 가 빈 배열로 온다. 이 경우 프론트가 같은 반경(3km)으로 `GET /api/places/nearby?type=hospital` 을 한 번 더 조회해 카드를 보여 준다. 둘 다 실제 DB 조회이며, `hospitals` 가 채워지면 자동으로 원래 경로(진료비 포함)를 쓴다.

## 5. 반응형

- PC: 380×최대 640px 창, 우측 하단, 내부 스크롤.
- 모바일(760px 이하): 전체 화면 채팅, `visualViewport` 로 키보드가 열려도 입력창이 보이게 높이를 맞춤, 입력 글자 16px(iOS 확대 방지), 버튼 56px. 채팅이 지도를 완전히 덮으므로 지도 조작과 충돌하지 않는다.
- `prefers-reduced-motion` 이면 애니메이션 끔.

## 6. 테스트

```bash
# Windows 에서 WSL 경로(\\wsl.localhost)는 Node 가 못 읽으므로 WSL 안이나 복사본에서 실행
node --test 02_frontend/map-poc/tests/chat-core.test.js
```

결과: 8개 통과 (입력 검증, 대화 기록 자르기, 위치 포함 규칙, 카드 변환·비공개 처리, 보조 조회 판단, 기본값, 오류 문구·포맷, 추천 질문).

브라우저 확인 (2026-11-24, 로컬 API + Gemini):
- 추천 질문 전송 → 답변·선택지·병원 카드 5곳 표시
- 직접 입력 + Enter 전송
- "지도에서 보기" → 지도 이동, 마커·정보창 표시(채팅창에 가리지 않음)
- 503 강제 → 오류 안내와 다시 시도 → 정상 응답, 질문 중복 없음
- Esc 닫기, 대화 초기화 → 환영 화면
- 모바일 375×812: 전체 화면, 가로 스크롤 없음
- 기존 지도: 마커·목록·업종 필터 그대로 동작, 콘솔 오류 없음
