# 10. 배포·운영 가이드 (팀 공유용)

> 냥집사를 인터넷에 올린 구성과, 팀원이 코드를 고친 뒤 실제 사이트에 반영되는 방법을 정리합니다.
> **비밀번호·API 키 값은 이 문서와 저장소에 절대 적지 않습니다.** (이름만 적음)

## 1. 접속 주소

| 구분 | 주소 | 비고 |
|---|---|---|
| **서비스 (공유용)** | https://nyangjipsa.vercel.app | 팀원·교수님께 보낼 주소 |
| 랜딩 페이지 | https://nyangjipsa.vercel.app/intro | 광고·공유 유입용 |
| 백엔드 API | https://nyangjipsa-api.onrender.com | 화면 없음. `/health`, `/health/db` 로 상태 확인 |

## 2. 구성 (전부 무료 플랜)

```
사용자 브라우저
   │  https://nyangjipsa.vercel.app
   ▼
Vercel (React 화면, 02_frontend)
   │  /api/* , /health 는 vercel.json 의 rewrite 로 Render 에 전달 (같은 출처 → CORS·쿠키 설정 불필요)
   ▼
Render (Rust 백엔드, 01_backend, Docker, 싱가포르)
   │  DATABASE_URL (Neon 직접 연결 주소)
   ▼
Neon (PostgreSQL 18 + PostGIS, AWS 싱가포르)
```

외부 서비스: 네이버 지도(화면), 카카오 로그인·길찾기, 구글 로그인, Gemini(챗봇), Brevo(인증 메일 SMTP), Amplitude(분석)

참고: `02_frontend/functions/` 는 Cloudflare Pages 용으로 만들어 둔 프록시입니다. 지금은 Vercel 을 쓰므로 사용하지 않습니다.

## 3. 코드를 고치면 사이트에 어떻게 반영되나요?

**`main` 브랜치에 합쳐지면 자동으로 배포됩니다.** Render·Vercel 계정에 들어갈 필요가 없습니다.

| 바뀐 폴더 | 자동 배포 | 걸리는 시간 |
|---|---|---|
| `02_frontend/` | Vercel | 1~2분 |
| `01_backend/` | Render (Docker 빌드) | 5~10분 |
| 그 외 (`04_docs/` 등) | Vercel 만 다시 빌드 (화면 변화 없음) | 1~2분 |

### PR 올리기 전 체크 (기존 팀 규칙 그대로)
```bash
# 01_backend
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo sqlx prepare -- --all-targets   # 쿼리를 바꿨다면 필수, .sqlx/ 도 커밋
# 02_frontend
npm run check
```
- Render 는 DB 없이 빌드합니다(`SQLX_OFFLINE=true`). **`.sqlx/` 를 커밋하지 않으면 배포 빌드가 실패**합니다.
- `02_frontend/package.json` 에 패키지를 추가하면 `package-lock.json` 도 함께 커밋합니다.

## 4. DB(Neon) 변경할 때 ⚠️ 중요

Render 는 **마이그레이션을 자동으로 실행하지 않습니다.** 새 마이그레이션(`01_backend/migrations/00XX_*.sql`)이 있는 PR 은 아래 순서를 지킵니다.

1. DB 관리자에게 알림 (Neon 접속 정보는 관리자만 가짐)
2. 관리자가 Neon **백업** (`pg_dump`, 아래 6절)
3. 관리자가 Neon 에 마이그레이션 실행 (`DATABASE_URL=<Neon 직접 연결 주소> sqlx migrate run`)
4. 그다음 PR 을 `main` 에 합침 → Render 자동 배포

- 이미 적용된 마이그레이션 파일은 수정하지 않고 새 번호 파일을 추가합니다 (기존 규칙).
- 가능하면 **표·칸 추가처럼 기존 데이터를 바꾸지 않는 변경**으로 만듭니다. 그러면 배포 순서가 조금 어긋나도 서비스가 멈추지 않습니다.
- 병원·진료비 데이터 보호 규칙은 `CLAUDE.md` 와 `.claude/skills/hospital-data-sync/SKILL.md` 를 따릅니다.

현재(2026-11-26) Neon 상태: 마이그레이션 **0001~0008** 적용, 업소 58,512 / 병원 5,573 / 병원 진료비 81,419 / 지역 진료비 2,978 / 고양이 친화병원 93, 용량 약 66MB (무료 한도 1GB)

## 5. 환경변수 (값은 각 대시보드에만 있음)

### Render (`nyangjipsa-api`)
| 이름 | 내용 |
|---|---|
| `DATABASE_URL` | Neon **직접 연결** 주소 (`-pooler` 없는 주소) |
| `APP_ENV` | `production` |
| `APP_BASE_URL` | `https://nyangjipsa.vercel.app` (메일 링크·소셜 로그인 후 이동, 회원 API 허용 출처) |
| `PUBLIC_BASE_URL` | `https://nyangjipsa-api.onrender.com` (공유 링크 `/s/{code}` 주소) |
| `RUST_LOG`, `SYNC_INTERVAL_HOURS=0` | 로그 수준, 자동 동기화 끔(무료 서버는 잠들어서 주기 실행이 불안정) |
| `GEMINI_API_KEY` | 챗봇 |
| `KAKAO_REST_API_KEY` | 길찾기 (도보·대중교통) |
| `KAKAO_LOGIN_REST_API_KEY`, `KAKAO_LOGIN_CLIENT_SECRET`, `KAKAO_LOGIN_REDIRECT_URI` | 카카오 로그인 |
| `GOOGLE_LOGIN_CLIENT_ID`, `GOOGLE_LOGIN_CLIENT_SECRET`, `GOOGLE_LOGIN_REDIRECT_URI` | 구글 로그인 |
| `MAIL_MODE=smtp`, `SMTP_HOST`, `SMTP_PORT=2525`, `SMTP_TLS=starttls`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` | 인증 메일 (Brevo). Render 무료는 25·465·587 포트를 막아서 **2525** 사용 |
| `PROXY_SHARED_SECRET` | Cloudflare 프록시용 (Vercel 에서는 미사용) |

### Vercel (`nyangjipsa`, Root Directory `02_frontend`)
| 이름 | 내용 |
|---|---|
| `VITE_NAVER_MAP_CLIENT_ID` | 네이버 지도 Client ID (브라우저 공개용) |
| `VITE_AMPLITUDE_API_KEY` | (선택) 분석 이벤트 |

환경변수를 바꾸면 Render 는 "Save, rebuild, and deploy", Vercel 은 Redeploy 해야 반영됩니다.

## 6. 계정·콘솔과 담당

무료 플랜이라 Render 는 **팀원 초대가 안 됩니다.** 설정·로그·비밀값은 저장소 관리자(`wjdgus6480`)가 관리합니다. 운영 설정을 바꿔야 하면 관리자에게 요청하세요.

| 서비스 | 무엇 | 설정 메모 |
|---|---|---|
| Vercel | 화면 배포 | Production 브랜치 `main` |
| Render | 백엔드 배포 | 브랜치 `main`, Root `01_backend`, Health Check `/health` (오타 주의: 예전에 `/healthㅠ` 로 배포 실패한 적 있음) |
| Neon | DB | 직접 연결 주소 사용. 5분 쉬면 자동 중지(첫 요청 조금 느림) |
| 네이버 클라우드 Maps | 지도 | Web 서비스 URL 에 `https://nyangjipsa.vercel.app`, `http://localhost:5173` 등록. **새 주소에서 지도가 안 뜨면 여기 등록** |
| 카카오 디벨로퍼스 앱 `냥집사` | 로그인 | Redirect URI: 배포 주소 + `http://localhost:5173/api/auth/kakao/callback`. 동의항목 **카카오계정(이메일) 필수** → 인증 메일 없이 바로 가입 |
| 카카오 (다른 앱) | 길찾기 | 카카오맵 사용 설정 ON 인 앱의 REST 키 |
| Google Cloud 프로젝트 `nyangjipsa` | 구글 로그인 | OAuth 클라이언트 `nyangjipsa-web`. **'테스트 중' 상태 → 테스트 사용자로 등록된 Gmail 만 로그인 가능**(최대 100명). 공개하려면 개인정보처리방침 페이지 필요 |
| Brevo | 인증 메일 | 무료 하루 300통. 보내는 주소가 Gmail 이라 **스팸함으로 갈 수 있음**. SMTP 키는 90일 미사용 시 만료 |

### Neon 백업 (관리자)
```bash
pg_dump "<Neon 직접 연결 주소>" -Fc -f nyangjipsa-YYYYMMDD.dump   # PostgreSQL 18 클라이언트
```
백업 파일은 저장소에 올리지 않습니다.

## 7. 무료 플랜 주의사항

- **첫 접속이 느릴 수 있음**: Render 무료 서버는 15분 동안 요청이 없으면 잠들고, 깨는 데 약 50초. **시연 전에 미리 한 번 접속**해 두세요.
- Render 무료: 월 750시간(1개 서비스는 충분), 메모리 512MB.
- Neon 무료: 저장 1GB, 월 100 CU-시간.
- Vercel Hobby: 개인·비영리 용도.
- Gemini 무료 한도: 서버에 전체 분당 10회 / 사용자당 분당 5회 제한이 걸려 있음.

## 8. 로컬 개발은 그대로

로컬 개발 방법은 바뀌지 않았습니다 (`README.md`, `03_tech-stack/TECH_STACK_AND_SETUP.md`).
- 카카오·구글 로그인 Redirect 에 `http://localhost:5173/...` 이 등록돼 있어 로컬에서도 시험할 수 있습니다.
- Gemini·카카오 키는 **각자 무료로 발급**해서 자기 `.env` 에 넣는 것을 권장합니다 (공용 무료 한도를 나눠 쓰지 않도록).

## 9. 비밀값 다루기

- 비밀번호·키는 **`.env`(Git 제외)와 각 대시보드에만** 둡니다.
- 카카오톡·디스코드·이메일·GitHub 이슈에 **그대로 붙여넣지 않습니다.** 꼭 전달해야 하면 Bitwarden Send 같은 **1회 열람·자동 만료 링크**를 씁니다.
- 실수로 노출됐다면 해당 서비스에서 **새 키 발급 → 대시보드 교체 → 예전 키 삭제** 순서로 바꿉니다.

## 10. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 사이트가 30초 넘게 안 뜸 | 서버가 깨는 중일 수 있음. 1분 뒤 새로고침. `https://nyangjipsa-api.onrender.com/health` 확인 |
| 지도가 하얗거나 "인증 실패" | 네이버 클라우드 Web 서비스 URL 등록 여부 |
| 로그인·회원가입 POST 가 403 | Render `APP_BASE_URL` 이 실제 화면 주소와 같은지 |
| 백엔드 배포 실패 | Render 로그. 흔한 원인: `.sqlx/` 미커밋, Health Check 경로 오타, 마이그레이션 미적용 |
| 인증 메일이 안 옴 | 스팸함 확인, Brevo 일일 한도·SMTP 키 만료 |
| 구글 로그인 "액세스 차단됨" | Google Cloud 테스트 사용자에 그 Gmail 등록 |
