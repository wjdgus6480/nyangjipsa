## 3. 주요 결정 사항

| 결정 | 이유 |
|---|---|
| SQLx **0.9.1** 유지 | 0.8은 2025-05 이후 업데이트 중단. 0.9.0은 2026-05 출시 후 널리 사용됨 |
| geozero 미사용, 공간 처리는 SQL에서 | geozero 0.15.1은 SQLx 0.8만 지원 → 충돌 |
| 좌표: `geography(Point, 4326)`, Rust는 `f64` lon/lat, **X=경도 Y=위도** | 의존성 없이 단순하게 처리 |
| TLS: sqlx `tls-rustls-aws-lc-rs` + reqwest `rustls` | reqwest 0.13 기본이 aws-lc-rs → 암호화 구현을 하나로 통일 |
| `query!` 매크로 + `.sqlx/` 커밋 | 컴파일 시 SQL 검증 + DB 없이도 빌드 가능 |
| `01_backend/.env` → `../.env` 링크 | SQLx 매크로는 `Cargo.toml` 폴더의 `.env` 만 읽음 (빌드 중 실제 확인) |
| uuid, chrono 제외 | 현재 기능에 불필요 |
| 폴더 번호 `01_~04_`, 코드 폴더는 영문 | Rust 모듈명 제약, 괄호 폴더명은 셸에서 따옴표 필요 (테스트로 확인) |
| **WSL2 방식을 팀 기본으로** | 스마트 앱 컨트롤 유지, 배포 환경(Linux)과 동일 |

## 4. 스마트 앱 컨트롤 문제와 WSL2 전환

- 증상: Windows에서 `cargo build` 시 모든 빌드 스크립트가 `애플리케이션 제어 정책에서 이 파일을 차단했습니다. (os error 4551)`, `cargo fmt`/`cargo clippy` 도 차단
- 원인: 스마트 앱 컨트롤(`VerifiedAndReputablePolicyState = 1`)이 서명·평판 없는 실행 파일을 차단. Rust는 빌드마다 새 실행 파일을 만들기 때문에 피할 수 없음
- 결정: 보안 설정을 바꾸지 않고 **WSL2 Ubuntu 안에서 빌드**
- 이전 방법:
  - 원본 `C:\Users\wjdgu\Desktop\조별과제\03_vet-map` 은 **백업으로 보존** (삭제 안 함)
  - `.git`(Windows 전용 설정, 커밋 0개), `target/` 제외하고 복사 → 파일 27개 내용 동일 확인
  - 파일 권한 644/755로 정리 (`/mnt/c` 파일은 모두 실행 권한으로 보이므로)
  - `.env` 는 권한 600으로 복사, 내용 출력 없이 원본과 동일함만 확인
  - Linux에서 `git init -b main` 새로 시작
  - DB 컨테이너·볼륨은 그대로 사용 (WSL에서 `127.0.0.1:5432` 접속 확인)
- 진행 중 겪은 문제:
  - Ubuntu `sudo` 비밀번호 입력이 앱 내장 터미널에서 `wsl` 로 전달되지 않음 (시간 초과) → 사용자가 직접 패키지 설치
  - rustup을 기본 툴체인 없이 설치 → 프로젝트 밖 `cargo install` 실패 → `rustup default 1.100.0`
  - `query!` 매크로가 상위 폴더 `.env` 를 못 읽음 → 링크로 해결
