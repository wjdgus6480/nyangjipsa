# 03. vet-map 작업 병합 및 연동 기록

| 항목 | 내용 |
|---|---|
| 작업일 | 2026-11-24 |
| 범위 | 팀원 `nyangjipsa`(5개 업종 수집, 지도 PoC, 05_data) + vet-map(병원 진료비, 챗봇, 자동 동기화) 병합 |

## 1. 병합 결정 (선택지로 확정)

| 결정 | 선택 |
|---|---|
| 병원 DB 구조 | `animal_businesses` 가 공공데이터 원본 5종의 정본, `hospitals` 는 거기서 파생되는 서비스용 병원(진료비 연결용). `hospitals.external_id = animal_businesses.mng_no` |
| 폐업 정책 | **폐업은 저장하지 않고 삭제로 통일** (휴업·취소/말소는 유지). 미용·위탁은 자택 영업일 수 있어 개인정보 보관도 줄임 |
| 진료비 통계 | 현재 구조 유지(`region_fees`: 고양이·시군구 평균 2,978건). 팀원 CSV 와 대조만 함 |

## 2. 진료비 중복 데이터 대조

`05_data/02_전국동물병원진료비` CSV(고양이+공통, 시군구, 데이터 있음 4,864건)와 `region_fees`(2,978건)를 대조: **일치 2,978 / 값 다름 0 / 우리에만 있음 0**. 같은 출처(농림축산식품부 2025년 조사)라 덮어써도 변화가 없다. 팀원 CSV 는 시도 단계와 중간값·최저·최고, 개·공통 항목까지 갖고 있어 확장 시 원천으로 쓸 수 있다.

## 3. 바뀐 것

| 영역 | 내용 |
|---|---|
| 마이그레이션 | 0001~0003 은 그대로, **0004 추가**(`hospitals` 확장, `region_fees`, `hospital_fees`). 이미 0003 까지 적용한 DB 는 `sqlx migrate run` 만 하면 됨 |
| 수집 | 수집 로직을 `ingest.rs` 라이브러리로 옮기고 `collect` 가 사용. 폐업 삭제, `--incremental`(저장된 마지막 변경 시각 − 1일) 추가 |
| 병원 파생 | `collector.rs`: 수집한 병원을 `hospitals` 로 파생(병원 id·진료비 유지). 병원 폐업 시 두 테이블에서 함께 삭제 |
| 자동 동기화 | `sync.rs`: 수집 → 파생 → 신규 병원 더미 진료비. `SYNC_INTERVAL_HOURS`(기본 0 = 꺼짐) |
| 연동 | `/api/places/nearby` 의 병원에 `hospital_id` 추가, `GET /api/hospitals/{id}` 로 진료비 조회, 챗봇이 약국·미용·장묘·위탁도 검색 |
| 기반 코드 | 설정 Debug 에서 비밀값 숨김 유지, 개발 모드에서만 CORS 허용 유지 |
| 챗봇 | `chat/`: Gemini 1회 호출, 키워드·중요도·선택지, 재시도·보조 모델, 호출 상한, 캐시, 대체 응답 |

## 4. 통합 중 발견해 고친 문제

- **병원이 폐업으로 바뀌어도 `hospitals` 에 남음**: 원본(`animal_businesses`)만 지우면 서비스용 병원 행이 남아 폐업 병원이 계속 검색됨. 원본 삭제와 함께 `hospitals`(진료비 CASCADE)도 삭제하도록 수정하고 회귀 테스트(`tests/merge_integration.rs`) 추가.

## 5. 팀 결정이 필요한 것

| 항목 | 내용 |
|---|---|
| 미용·위탁 좌표 공개 | 02 번 문서의 미결 사항과 같음. 챗봇은 번지가 가려진 업소의 정확한 좌표·전화번호를 주지 않도록 해 둠. `/api/places/nearby` 는 기존 그대로(정확한 좌표 공개) |
| 자동 동기화 기본값 | 놀라지 않도록 꺼짐(`SYNC_INTERVAL_HOURS=0`)으로 둠. 운영에서 켤지 결정 |
| 더미 진료비 | 지역 평균 ±20% 임의 값(`is_dummy=true`). 실제 가격 확보 시 교체 |
| 증분 수집 검증 | `cond[DAT_UPDT_PNT::GTE]` 로 폐업 전환이 모두 잡히는지는 장기 운영 확인 필요. 주기적으로 전체 수집(`collect all`)도 권장 |

## 6. 검증

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `cargo sqlx prepare --check`, DB 없이 `SQLX_OFFLINE=true cargo build --all-targets` 통과
- 실제 DB 로 검증: vet-map 데이터(병원 5,343곳, 진료비 79,086건)를 별도 DB 로 복사해 통합 수집 후, 기존 병원 id·진료비 가격이 그대로인지 비교
